# 运单复制核对台

本地核对页：判断备库少单到底是**同步落后**还是**确实漏了**。

Flask + SQLite，两库分离（主库 / 备库），Docker Compose 启动。

## 快速开始

```bash
docker compose up --build
# 打开 http://localhost:8000
```

首次启动会自动写入示例历史（主库为空时），并内置样例缺陷：**第 3 笔提交里的
`WB1008` 在备库被静默丢弃**。用页面即可定位它。

本机无 Docker 时：

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
AUTO_SEED=1 DROP_RULES='{"3":["WB1008"]}' python run.py
```

## 核对方法

1. 总览页可照常**写入主库**（每次写入生成一笔新提交）和**逐批推进备库**。
2. 进入「按提交核对」，选择**主库提交号**与**运单号区间**，点击核对。
3. 备库 `已应用提交 < 所选提交` → 显示 **待同步**，不给结论：此时少单可能只是没追上。
4. 备库已追到所选提交 → 按两库**在该提交的记录**核对，列出：
   - **少单**：主库有、备库无
   - **多单**：备库有、主库无
   - **状态不符**：两库都有但状态不同

### 为什么核对点稳定

主库用追加式 `change_log` 记录每笔提交的增量，备库用 `apply_log` 记录实际收到的
增量。任一提交 `C` 的两库状态都由**重放 `commit_no <= C` 的增量**得到，每次只做内存
折叠，不落盘整表副本。因此：

- 主库继续写入新提交、备库继续追赶，都不改变「截至提交 `C`」的核对结果；
- 未追到 `C` 时不做判断，避免把「落后」误报成「漏单」。

两库均只有「增量日志 + 当前状态缓存」两类表，没有按批保存的整表快照。

## 示例数据

| 提交 | 内容 | 说明 |
|------|------|------|
| #1 | WB1001–1004 入库 | 换版前 |
| #2 | WB1005–1007 入库 | 换版前 |
| #3 | WB1008–1010 入库 | **备库漏掉 WB1008** |
| #4 | WB1003/1006/1009 状态回填 | 规则换版批 |
| #5 | WB1011–1012 新增 | 换版后 |

选提交 #3、区间 `WB1001`–`WB1010`：落后时显示待同步；追赶后列出少单 `WB1008`。

## 配置

| 环境变量 | 默认 | 说明 |
|----------|------|------|
| `PRIMARY_DB` / `REPLICA_DB` | `/app/data/*.db` | 两库文件路径 |
| `DROP_RULES` | `{"3":["WB1008"]}` | 模拟漏同步：`提交号 -> [运单号]`，JSON |
| `AUTO_SEED` | `1`（compose） | 主库为空时写入示例历史 |
| `PORT` | `8000` | 监听端口 |

`DROP_RULES` 设为空字符串 `""` 即关闭缺陷注入，备库将完全一致。
